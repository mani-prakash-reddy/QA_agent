# Purpose-built test applications

Three small applications written to be **test targets with known ground truth**: every rule, role and screen is
in the source, so the BRD that goes with each one can be checked against what is really there. They are
deliberately unlike each other and unlike Juice Shop, Redmine and Gitea.

| App | Style | Port | What it exercises |
|---|---|---|---|
| **LeaveTrack** (`leavetrack.py`) | single-page app, history-API routes | 3101 | 3 roles (employee, manager, HR); HR signs in with **TOTP**; modals with field rules; a reject dialog; role-only pages; tabs by query string |
| **Stockroom** (`stockroom.py`) | server-rendered, full page loads | 3102 | 3 roles incl. a **read-only** one; search, filter and **pagination** by query string; a **3-step wizard**; tabs; a delete confirmation page; CSV export link; settings form |
| **HelpDesk** (`helpdesk.py`) | hash-routed single-page app (`#/tickets`) | 3103 | 3 roles; radios, a file input, a textarea minimum; **sessions that expire** (`DEMO_HELP_SESSION_TTL`, default 120 s) so the crawler must sign in again |

```bash
docker compose --profile demo-leave --profile demo-stock --profile demo-help up -d --build demo-leave demo-stock demo-help
```

From the worker container use `http://demo-leave:3000`, `http://demo-stock:3000`, `http://demo-help:3000`;
from the host `http://localhost:3101|3102|3103`.

## The BRDs and their answer keys

`../brds/{leavetrack,stockroom,helpdesk}.{md,docx,pdf}` are generated by `../build_app_brds.py` from one
table, which also writes `*.gold.json` (expected requirements, for `backend/scripts/eval_brd_extraction.py`) and
`*.mapping-gold.json` (expected requirement-to-screen links, for `eval_mapping.py`). Each BRD contains:

- **Numeric rules** the app really enforces (lengths, ranges, minimums) and rules for who may do what.
- **Requirements the app does not implement** (email notification, spreadsheet export, profile picture, bulk
  upload, ratings, invitations, a 7-year retention rule): the gap report must say so.
- **Vague requirements** ("easy to submit", "feel fast", "pleasant to use"): they must be flagged, not guessed.
- **A feature the BRD omits**: LeaveTrack's Profile page (the undocumented-screens report should list it).

## Mock TestRail

`mocktestrail.py` (profile `demo-testrail-mock`, `http://demo-testrail-mock:3000` from the containers, `http://localhost:3104` from the host) is a **stand-in** for TestRail's API, not TestRail: log in as `qa@demo.test` with the key `mock-key` under Integrations to try *Push to…* without an account.
